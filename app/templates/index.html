from agnara import App, StandardEffect, Risk

contacts = App("contacts")

@contacts.capability(
    description="Receive a contact request.",
    effects=(StandardEffect.DATABASE_WRITE,),
    risk=Risk.LOW,
    idempotent=False
)
async def submit(name: str, email: str, message: str) -> None:
    # Business logic goes here. Agnara handles validation, 
    # execution identity, telemetry, and policies.

The Capability-First Architecture

Traditional frameworks entangle business logic with transport protocols (HTTP handlers, MCP tools, CLI commands). Agnara inverts this: the capability owns the meaning, the transport owns how it is reached.

Runtime Architecture

Compile validation, dependencies, and policies before invocation.

1. App & Registry

Capabilities are grouped into Bounded Contexts (Apps) and compiled into a FrozenCapabilityRegistry.

↓
2. Execution Plan

Agnara statically analyzes signatures to compile a plan encompassing: schemas, policies, dependencies, and telemetry.

↓
3. Capability Runtime

The CapabilityRuntime manages the active ExecutionContext, enforcing policies, injecting singletons, and returning canonical Success or Failure outcomes.

Core Features

Typed Schemas

Python type hints form the contract. Agnara automatically validates inputs before the capability is even invoked.

Dependency Injection

A native, highly performant DIContainer handles singleton scopes, generator cleanup, and dependency inversion.

Execution Policies

Enforce authorization, risk levels, and idempotency guarantees deterministically via the runtime.

Canonical Outcomes

Capabilities return standard Success or Failure objects. Expected domain errors are never thrown as exceptions.

Agent-Readable Metadata

Standard effects, risk markers, and descriptions allow autonomous agents to safely reason about and orchestrate capabilities.

Native Introspection

Explore your application's capabilities securely via the builtin HTTP Explorer or discovery APIs.

Built for humans.
Designed for agents.

Agnara treats AI agents as first-class consumers of your application architecture.

  • Stable capability identifiers
  • Machine-readable Risk and StandardEffect markers
  • Introspectable, strongly-typed schemas
  • Explicit execution boundaries and outcomes

This strict semantic layer allows agents to autonomously orchestrate operations with confidence, without screen-scraping UIs or guessing REST semantics.

The form below hits a standard Starlette presentation route. The route maps the HTML POST payload into an Agnara Invocation and executes it via the CapabilityRuntime.

SQLite and SQLAlchemy are injected via Agnara DI. The capability is unaware of both Starlette and the database engine.
